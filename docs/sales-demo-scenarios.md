# Sales demo scenarios

FinPilot includes a sandbox-gated sales demonstration API that provisions an isolated demo account with synthetic customers, verification examples and typed scenario records. It is designed for demonstrations and controlled testing, not for loading real bank/customer data.

## API and access model

The sales-demo router is rooted at `/api/v1/sandbox/demo` and is enabled only when sandbox access is enabled in the application configuration.

| Method | Route | Purpose | Access |
|---|---|---|---|
| POST | `/accounts` | Create a demo account with synthetic scenarios | JWT; designated Sales Demo Manager role |
| GET | `/dashboard` | Account-level dashboard/usage snapshot | Sandbox API key; `sandbox:read` |
| GET | `/scenarios` | List guided scenario catalogue | Sandbox API key; `sandbox:read` |
| GET | `/verifications` | List seeded verification outcomes | Sandbox API key; `sandbox:read` |
| GET | `/records` | List demo records, optionally filtered by record type | Sandbox API key; `sandbox:read` |
| POST | `/reset` | Reset demo customers, verification samples and scenario records | Sandbox API key; `sandbox:admin` |

Consult the running OpenAPI schema for exact query fields and request/response shapes.

The create response includes the API test key, which is shown once. Store it securely and use the configured sandbox authentication header expected by the API. A sandbox API key is a credential: do not put it in screenshots, support tickets, source files or public demo material.

## Scenario catalogue

| Scenario | What to demonstrate | Synthetic data source |
|---|---|---|
| Customer onboarding | Individual vs business profiles, risk bands and onboarding states | `sandbox_customers` attributes |
| Verification outcomes | Approved, rejected and manual-review examples | `sandbox_verifications` static results |
| Compliance review | High-risk case, indicators, evidence needed and reviewer action | `sandbox_demo_records` (`COMPLIANCE_CASE`) |
| AML alert | Cross-border velocity signal, amount/time context and investigation checklist | `sandbox_demo_records` (`AML_ALERT`) |
| AI recommendation | Risk score, confidence, risk factors and suggested next step | `sandbox_demo_records` (`AI_RISK_RECOMMENDATION`) |
| Investigation summary | Observations, confirmed sample facts, outstanding questions and actions | `sandbox_demo_records` (`INVESTIGATION_SUMMARY`) |
| Usage dashboard | Example API, verification, AI, workflow and report volumes | `sandbox_demo_records` (`DASHBOARD`) and dashboard API |
| Compliance report | Reporting period, reviewed customers, alerts and escalations | `sandbox_demo_records` (`REPORT`) |
| Due diligence workflow | Illustrative task stages and role handoffs | `sandbox_demo_records` (`WORKFLOW`) |

The dashboard's `usage_sample` is a static presentation dataset. It is not actual billing, production usage or a query of the product-usage analytics tables.

## Safe demonstration sequence

1. Confirm sandbox is enabled and use a non-production deployment.
2. Have an authorized Sales Demo Manager create a synthetic demo account.
3. Capture the one-time test key in an approved secret store or secure local environment variable.
4. Call the dashboard, scenarios, verification and records routes using the demo key and least-privilege permissions.
5. Demonstrate a reset only when the audience understands that it deletes synthetic demo records for that account; retain no irreplaceable real data in the demo account.
6. Disclose which outputs are fixed sample records and which are generated by live backend logic/provider adapters.

## Boundaries

- The sales demo is not a real bank tenant and must not contain personal or financial data from a real customer.
- Demo record values are synthetic seeded examples; a plausible narrative is not a production risk signal.
- The sample usage dashboard is static presentation data, not metering evidence.
- AI behavior depends on the configured AI provider. Mock mode does not call a live model.
- Sandbox webhook simulation does not send outbound webhook requests.

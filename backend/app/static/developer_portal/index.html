01 / ACCESS

Authentication

Bearer JWT · X-API-Key

FinPilot supports two distinct authentication patterns. Most application endpoints use a short-lived JWT access token. Partner integration endpoints explicitly configured for key permissions use an API key in the X-API-Key header.

01

Sign in with JWT

Authenticate using an active FinPilot user. The login response contains an access token and refresh token. Send the access token as a Bearer token.

POST/api/v1/auth/login
curl -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"developer@example.com","password":"YOUR_PASSWORD"}'

Use the data.access_token value from the successful response in the Authorization header. Do not ship user passwords or JWTs in browser applications.

02

Use a partner API key

For API-key-authenticated partner endpoints, send the secret using X-API-Key. Keys are tenant-scoped, permission-scoped, revocable, and shown only once on creation.

GET/api/v1/integrations/customers
curl "$BASE_URL/api/v1/integrations/customers?limit=25" \
  -H "X-API-Key: $FINPILOT_API_KEY"

API keys are not JWTs and do not inherit user roles. The current partner integration route requires customers:read. Other endpoints may still require JWT authentication.

Token handlingKeep secrets in a server-side secret manager or environment variable. Never commit credentials, paste production secrets into tickets, or embed them in client-side source code.
02 / DATA

Customer APIs

Open customer operations ↗

Customer records are isolated by tenant. User-based endpoints additionally enforce role permissions; partner reads are restricted to the tenant attached to the API key.

POST/api/v1/customersCreate a customer (JWT; authorized role)
GET/api/v1/customersSearch and paginate customers (JWT)
GET/api/v1/customers/{customer_id}Retrieve a customer (JWT)
GET/api/v1/integrations/customersRead customer collection (API key: customers:read)

Create a customer example

curl -X POST "$BASE_URL/api/v1/customers" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Amina",
    "last_name": "Example",
    "email": "amina@example.com",
    "phone_number": "+12025550123",
    "status": "NEW"
  }'

The create route is intended for authorized user roles, not for the read-only partner key described above. Check the live OpenAPI schema for the complete request model and any additional field requirements.

05 / EVENTS

Webhooks

Signed callbacks

Register an HTTPS endpoint to receive subscribed events. FinPilot returns a signing secret only when the webhook is created; store it securely and use it to verify the X-FinPilot-Signature header before processing an event.

POST/api/v1/webhooksCreate a webhook (JWT administrator)
GET/api/v1/webhooksList webhook subscriptions

Webhook event types currently declared

customer.createdcustomer.updatedverification.completedverification.failedcase.createdcase.closed
{
  "id": "event-uuid",
  "type": "customer.created",
  "created_at": "2026-01-01T12:00:00+00:00",
  "data": { "id": "customer-uuid", "status": "NEW" }
}

Webhook callback registration requires a public HTTPS destination; private, localhost, or reserved IP addresses are rejected. Do not assume delivery is exactly once: make handlers idempotent and consult delivery history/retry status in the API reference.

06 / DEBUGGING

Error handling

JSON responses

Most API errors use a consistent JSON envelope. HTTP status is the primary outcome signal; the message and optional validation details explain what failed.

{
  "success": false,
  "message": "Validation failed.",
  "data": null,
  "errors": [
    { "field": "email", "message": "Input should be a valid email address" }
  ]
}
400Bad RequestThe request is not allowed or a business rule was violated.
401UnauthorizedMissing, invalid, expired, or revoked credentials.
403ForbiddenThe authenticated identity lacks a required role or API-key permission.
404Not FoundThe resource could not be found in the authorized scope.
409ConflictA uniqueness rule or existing record prevents the operation.
422Validation FailedA path, query, or JSON body field failed validation.
429Rate LimitedSlow down and retry with backoff; honor Retry-After when present.
500Server ErrorUnexpected service or database error. Keep the request ID for support.
503UnavailableThe service may not be ready or a dependency is temporarily unavailable.
Debugging tipCapture the HTTP status, response body, timestamp, endpoint, and request ID response header when present. Never include passwords, bearer tokens, API keys, or sensitive customer data in support tickets.
